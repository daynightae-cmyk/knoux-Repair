# KNOUX REPAIR — البرومبت الملحمي لصناعة البصريات (UI/UX WORLD-CLASS)

> الوثيقة الأم لرؤية KNOUX REPAIR البصرية — تُسلَّم إلى مطوّر البصريات (Manus AI) لتشييد هوية بصرية عالمية من أول بكسيل في الـ Splash إلى آخر ظل في نافذة الإعدادات.

---

## 1. المهمة العظمى (THE GRAND MISSION)

أنت الآن **كبير مصممي البصريات** في KNOUX. مهمتك ليست "تحسين الواجهة" — مهمتك أن تحوّل منتجًا وظيفيًا قويًا إلى **تحفة بصرية تُشعر المستخدم بالفخر وهو يستخدمها**. KNOUX هو العرّاب الرقمي الذي يحمي أجهزة الناس؛ يجب أن **يبدو** كما يبدو شعور من يمسك سيفًا محفورًا بالضوء: فخامة، قوة، ثقة، وسحر تقني راقٍ.

كل بكسل قرار. كل حركة إحساس. كل لون رسالة.

**الشعار:** *الضوء يلمس الزجاج، والزجاج يحمي الجهاز.*

## 2. هوية المنتج (PRODUCT IDENTITY)

- **الاسم:** KNOUX REPAIR — نسخة الويب تحمل الاسم الفني `knoux-repair-nexus` (Nexus = نقطة التقاء كل أدوات الحماية في بُعد واحد).
- **المنصة:** Windows Repair / Cleanup / Security Suite — أداة إصلاح وصيانة وتشخيص وأمان متكاملة، ثنائية اللغة (العربية/الإنجليزية) مع دعم كامل RTL/LTR.
- **الجمهور:** المستخدم العادي (وليس المطوّر). لا كلمات تقنية في الواجهة: "نظّف جهازك"، "سرّع جهازك"، "افحص الإنترنت"، "حرّر مساحة"، "افحص القرص"، "افحص الأمان" — دائمًا لغة شعبية مباشرة.
- **المحتوى الوظيفي:** **100 أداة إصلاح حقيقية** موزعة على 10 أقسام (10 أدوات لكل قسم). كل أداة تُنفَّذ فعليًا عبر محرك تنفيذ حقيقي (PowerShell على Desktop / Local Bridge API على الويب). **ممنوع تمامًا أي مظهر زائف أو وظيفة وهمية أو console.log بدل التنفيذ.**

## 3. السطحان (THE TWO SURFACES)

المنتج يعيش على **سطحين** يجب أن يتنفسا من **رئة بصرية واحدة** — نظام تصميم موحّد، لكن لكل سطح تشريحه:

### السطح الأول: DESKTOP (WPF — Glass GUI)
- المسار: `Glass-GUI-Builder/src/KnouxRepair/`
- البنية: MVVM — `Views/` (XAML)، `ViewModels/`، `Services/`، `Themes/` (Colors, Animations, Controls, Typography, Variables)، `Resources/Strings.en.xaml + Strings.ar.xaml`، `Models/`، `Converters/`، `Controls/`، `Core/`.
- الشاشات: **SplashScreen** → **MainWindow** (نافذة زجاجية رئيسية بجانبين) → **DashboardPage** → **AllToolsPage** → 10 صفحات أقسام → **ToolDetailPanel** (عرض تفاصيل الأداة) → **ReportsPage** → **QuarantinePage** → **BackupsPage** → **SettingsPage** → **AboutPage** → **TestCenterPage**.
- الترجمة: `Strings.en.xaml` / `Strings.ar.xaml` — تبديل فوري بدون إعادة تشغيل + قلب كامل RTL/LTR (ThemeService).

### السطح الثاني: WEB (React — Nexus)
- المسار: `web-frontend/` (React 18 + Vite 6 + TypeScript + Tailwind + framer-motion + lucide-react + react-router)
- البنية: `src/App.tsx`، `components/` (SplashScreen, Sidebar, Dashboard, ToolGrid, DiagnosticConsole, PlaceholderPage, PageTransition, BridgeOffline)، `lib/api.ts` (عميل حقيقي لجسر التنفيذ)، `lib/i18n.ts` (AR/EN + RTL).
- جسر التنفيذ الحقيقي: `web-frontend/server/bridge.mjs` — API محلي (127.0.0.1) بسماح Allowlist يشغّل أدوات KNOUX الحقيقية. **الواجهة تستدعي هذا الجسر فقط — لا محاكاة، لا بيانات مزيّفة.**

## 4. فلسفة التصميم (DESIGN PHILOSOPHY)

نظامك البصري اسمه **"GLASS NEXUS"** — ثلاث ركائز:

1. **الزجاج العميق (Deep Glass):** شفافية هرمية باحتراف — طبقات زجاجية حقيقية (Backdrop blur، Border glow، Highlight edges)، الخلفية لا تموت بل تنبض خلف الزجاج بجزيئات ضوئية خافتة. الزجاج ليس ترفًا: إنه **قيمة المنتج نفسه** (حمى، وضوح، عمق).

2. **الضوء الحيّ (Living Light):** كل حالة تفاعل تُضاء: hover = توهّج خفيف عند الحواف، active = انضغاط زجاجي، focus = هالة مركزة، تعطّل = زجاج مصنفر. الضوء يروي القصة قبل أن يقرأ المستخدم كلمة.

3. **الحركة ذات المعنى (Purposeful Motion):** كل حركة تخدم المحتوى. المدة العالمية 150–300ms (سريع على Desktop، أنعم قليلًا على الويب). لا حركة عشوائية، لا إطارات مهدورة، لا زخرفة تبطئ العمل.

### منظومة الألوان (COLOR SYSTEM) — وسم Colors.xaml + Tailwind tokens

- **الوضع الافتراضي:** **داكن فاخر** (خلفية `#0B0F1A` عائلتها، زجاج `rgba(255,255,255,0.04–0.09)`، حدود `rgba(255,255,255,0.08)`).
- **الوضع الفاتح:** كامل الوجود — زجاج أبيض `rgba(255,255,255,0.55)` بظلال عميقة وحدود `rgba(0,0,0,0.08)`. كلا الوضعين **من الدرجة الأولى**، لا "dark first ثم فاتح مهمل".
- **اللون الأساسي (Primary):** أزرق كهربائي-نيلي `#4F7CFF` → تدرّجه نحو `#9F7AFF` (بنفسجي) للعناصر الثانوية. كل قسم يحمل تدرجه الخاص كـ **accent** (انظر الجدول أعلاه) يظهر في أيقوناته وكروته وحالاته.
- **الحالات:** Success `#2ED573` · Warning `#FFB020` · Error `#FF5A5F` · Info `#4F7CFF` — بأشكال توهّج (glow) تتناسب مع الزجاج، وليس أخضر/أحمر مسطّحًا.
- **نص:** `#F2F5FF` أساسي · `#9AA3BF` ثانوي · `#5C667F` خافت — عامل تباين ≥ 4.5:1 في كل الحالات.

### الخطوط (TYPOGRAPHY)

- **العربية:** خط عصري عالي القراءة (عائلة مثل IBM Plex Sans Arabic أو Cairo أو Tajawal) — **أوزان متعددة، وأرقام هندية/عربية متسقة عند الحاجة**. حروف عربية كبيرة الحجم تحتاج ارتفاع سطر 1.6+ وإمكانية تقطيع أوزان بدون اهتزاز عند تبديل اللغة.
- **الإنجليزية:** Segoe UI Variable / Inter — بنفس مقياس الحجم.
- **المقياس:** `Display 40/44` · `H1 28/34` · `H2 22/28` · `H3 18/24` · `Body 14/21` · `Caption 12/16` — ثابت في `Typography.xaml` و Tailwind tokens.

## 5. الـ SPLASH — البوابة السينمائية (CINEMATIC ENTRY)

الانطباع الأول يُصنع هنا. **يمنع** أن يكون الـ Splash نافذة بيضاء بكتابة. المطلوب مشهد افتتاحي من 3 مقاطع (2.2–3.0 ثانية كاملة، يمر بتخطٍّ عند النقر):

1. **ظهور الجوهر:** خلفية داكنة تولد منها **جزيئات ضوئية** تتجمع نحو المنتصف لتكوّن **شعار KNOUX** (حرف K منحوت من الزجاج) بتوهّج يزداد ثم يستقر. (Desktop: Gradient brushes + storyboard; Web: canvas/CSS + framer-motion).
2. **كتابة الاسم:** اسم المنتج يكتب حرفًا حرفًا (Fade+Track) مع سطر الشعار *"Your Digital Guardian"* يظهر تحت بمهلة قصيرة.
3. **الدخول:** الشعار ينكمش بسلاسة نحو زاوية النافذة/الهيدر (morph) بينما المشهد الرئيسي ينسكب من خلفه (Fade + Scale 0.98→1).

**معايير النجاح:** لا وميض، لا تدفق CPU، يعمل في الوضعين (داكن/فاتح) وفي RTL (اتجاه الكتابة والدخول معكوسان هندسيًا).

## 6. الكروت الاحترافية (THE SERVICE CARDS) — قلب المنتج

كل أداة من الـ 100 أداة تُعرض في **بطاقة خدمة احترافية** (Desktop: ToolDetailPanel أو AllTools grid؛ Web: ToolGrid). البطاقة ليست مربعًا فيه اسم — إنها **بوابة مضاءة** لعملية إصلاح:

```
┌────────────────────────────────────────────────┐
│  (أيقونة زجاجية داخل قرص مضيء بلون القسم)         │   ← الممرّ = تدرّج القسم
│  تنظيف الجهاز                                    │   ← اسم شعبي (إنساني) لا تقني
│  احذف الملفات المؤقتة وغير الضرورية بأمان.        │   ← وصف من سطرين كحد أقصى
│  ● ● ●  جاهز  │ مدة ٢ دقيقة                      │   ← شارة الحالة (أنيقة)
│  [ ▶ ابدأ التنظيف ]        [ تفاصيل ]            │   ← زر أساسي + ثانوي
└────────────────────────────────────────────────┘
   hover: ترتفع البطاقة 2px + توهّج الحواف + الأيقونة تكبر 5%
   hover على "تفاصيل": الكشف عن أثر لطيف للمعلومات التقنية (Diagnostics)
```

**حالات البطاقة (إلزامية في كل سطح):**
- `idle` — زجاج هادئ، شارة "جاهز".
- `loading` — شريط تقدّم **حقيقي مرتبط بالحدث الفعلي** (مراحل التنفيذ خطوة-خطوة مع نص يقول ماذا يحدث الآن: "جاري فحص…", "جاري التنظيف…"). ممنوع شريط وهمي يتحرك بلا دلالة.
- `success` — دفقة توهّج خضراء + علامة ✓ داخل قرص دوّار + ملخص النتيجة الحقيقية ("تم تحرير 1.03 GB").
- `error` — توهّج أحمر + رسالة بشرية واضحة + زر "التفاصيل التقنية" (log) — **لا تظهر أبدًا NullReferenceException أو stack trace للمستخدم، بل داخل Diagnostics فقط**.
- `cancelled` — حالة صادقة "أُلغيت" مع إبقاء النتائج الجزئية.
- `disabled/elevation` — إذا احتاجت الأداة Administrator غير متوفر: رسالة واضحة "يتطلب تشغيل التطبيق كمسؤول" مع إجراء توجيهي.

## 7. الأقسام العشرة على Desktop — التشريح الكامل لكل صفحة

البنية العامة لصفحة القسم: **هيدر زجاجي** (أيقونة القسم في قرص مضيء + العنوان الشعبي + عدد الأدوات + زر "تشغيل الكل" عند منطقيته) → **شبكة الكروت** (3 أعمدة، تتقلص إلى 2 ثم 1) → **لوحة التفاصيل** (ToolDetailPanel) تنزلق من الأسفل/الجانب.

لكل قسم متطلبات تخصّه:

- **01 System Maintenance:** بطاقات "إنشاء نقطة استعادة"، "فحص سلامة النظام" — أضف بطاقة حالة النظام أعلى الشبكة (عدادات حقيقية عبر P/Invoke: الذاكرة، تحميل المعالج، القرص) داخل لوحة زجاجية بجزيئات متحركة خافتة.
- **02 System Cleanup:** بعد التنفيذ الناجح أظهر "كمية تم تحريرها" كرقم ضخم في تصميم KPI زجاجي. بطاقة "تنظيف سلة المحذوفات" لها أيقونة متحركة عند النجاح.
- **03 Network Internet:** بطاقة "فحص الاتصال" تعرض في نتيجتها **ملخص ping/سرعة** حقيقي بتصميم موجة (waveform) بدل جدول تقني (data real: latency, packet loss).
- **04 Programs & Applications:** كروت إدارة البرامج تعرض حالة "يعمل/متوقف" بشارة حية.
- **05 Duplicate Files:** نتيجة الفحص بتصميم "جواهر مكررة": عدد الملفات المكررة + المساحة المهدرة كـ KPI مع إمكانية "حذف" أو "الانتقال إلى الحجر الصحي".
- **06 Disk Space:** مخطط دائري (Donut) زجاجي حي لكل قرص يعرض المساحة الحقيقية، يتحرك بسلاسة عند التحديث.
- **07 Services & Processes:** الأداة الأكثر "تقنية" — حوّلها بذكاء: قائمة العمليات بإيقاف/تشغيل بأزرار واضحة وحالات ملونة.
- **08 Performance:** بطاقة "إعادة تعيين الذاكرة" وغيرها — أضف **خط أداء متحرك** (Live sparkline) في رأس القسم يعرض الاستخدام اللحظي.
- **09 Security:** نغمة قرمزية خاصة. بطاقة "فحص الأمان" تظهر شاشة "قيد الفحص" بدرع يهتز بلطف ثم يُقفل بالنجاح. قسم الملفات المحجوزة (QuarantinePage) بتصميم "زنزانة زجاجية": كل ملف بطاقة صغيرة بأزرار استعادة/حذف نهائي.
- **10 Diagnostics Reports:** التقارير تُعرض كبطاقات PDF/HTML أنيقة مع معاينة وطباعة. TestCenter بإطار "مختبر" يخفي التعقيد خلف أوامر واضحة.

كل ما سبق مبني على **الأدوات الحقيقية الموجودة** (`01-…` إلى `10-…`، 10 لكل قسم) — لا تُنشئ قسمًا فارغًا ولا بطاقة بلا أداة.

## 8. الويب (NEXUS) — التشريح الكامل

`web-frontend/` نفس الروح، نفس النظام، تشريح مختلف:

- **SplashScreen.tsx:** نفس المشهد السينمائي (3 مقاطع) — لكن انتبه: إذا كان الجسر غير متصل اعرض حالة صادقة سريعة بدل إخفائها.
- **Sidebar:** زجاج جانبي (عائم، لا ملتصق) بأيقونات lucide داخل أقراص؛ القسم النشط = بلورة مضيئة بلون القسم تنتقل بسلاسة (LayoutId motion)؛ على المحمول يتحول لـ drawer منزلق مع Backdrop blur + قفل تمرير الصفحة الخلفية.
- **Dashboard.tsx:** يتغذى من `/api/system` الحقيقي (عناصر نظام فعلية) — **يمنع أي رقم ثابت** (لا "SECURITY: PROTECTED" دون مصدر). بطاقات: حالة الحماية، صحة القرص، الذاكرة — كلها real-time مع حالة خطأ صادقة عند انقطاع الجسر. تحته: نجوم الأدوات المفضلة (6 كروت كبيرة) + زر "كل الأدوات".
- **ToolGrid.tsx:** شبكة الكروت (انظر §6) — مرشّح بحث فوري + فلتر قسم + عدّادات حية، ودعم كامل RTL.
- **DiagnosticConsole.tsx:** وحدة التحكم المباشر للأداة — سطور ملوّنة حسب النوع (خطأ/تحذير/معلومة/نجاح)، شريط تقدم حقيقي، زر **إيقاف (Cancel)** يصل فعليًا للجسر (cancellation)، زر "نسخ التقرير".
- **PlaceholderPage:** لأي وجه لم يُربط بعد بالجسر، اعرض حالة **صادقة** إلزامية: شارة "قريبًا" + نص "هذه الواجهة قيد الربط بمحرك التنفيذ" — ممنوع تقديمها كأنها تعمل.
- **BridgeOffline:** عند انقطاع الجسر — بانر أنيق غير مذعِر: "محرك التنفيذ المحلي غير متصل — شغّل التطبيق الرئيسي أو ابدأ الجسر" + زر "إعادة المحاولة". زجاج مصفرّ، لا أحمر صارخ.
- **PageTransition:** 180–250ms Fade + Slide بـ 8px مع احترام اتجاه RTL (الدخول من اليمين عند العربية).
- **i18n + RTL:** العربية كاملة: `dir="rtl"` على الجذر، انعكاس الهندسة بالكامل (المسافات عبر logical properties، الأسهم والرموز الاتجاهية تنقلب، الحروف العربية بخط عربي أنيق على مستوى الخط اللاتيني).

## 9. الحركة الدقيقة (MICRO-INTERACTIONS) — قائمة إلزامية

1. **Buttons:** hover = توهّج حافة 1px بلون العنصر + خلفية أفتح بدرجة؛ active = Scale 0.97 داخل زمن 100ms؛ focus-visible = هالة 2px. Ripple خفيف على الأزرار الرئيسية (اختياري).
2. **Cards:** hover = ارتفاع 2px + توهّج + أيقونة تكبر 4–5%؛ الدخول للشبكة = Staggered fade-up (60ms بين البطاقات، دفعة واحدة عند كل صفحة — لا عند كل سكرول).
3. **Numbers / KPIs:** أي رقم يتغير (ذاكرة، مساحة، نتائج) يعدّ (Count-up 400ms) بأرقام ثابتة العرض لمنع الاهتزاز.
4. **Status dots:** نبض ضوئي (pulse) ناعم 2s للعناصر الحية.
5. **Skeleton:** أي تحميل شبكة/بيانات → زجاج مهزوز (Shimmer زجاجي شفاف يعبر البطاقة) — لا فراغ أبيض.
6. **مؤشر التقدم:** شريط بحركة "تدفق ضوئي" (indeterminate shimmer أثناء مرحلة مجهولة، نسبة مئوية فعلية أثناء مرحلة معروفة) — **الرقم حقيقي من التنفيذ**.
7. **Toast/Notifications:** تنزلق من حافة الاتجاه (RTL: من اليسار؟ لا — من الأعلى محايد) بشفافية زجاجية، 4 أنواع ملونة، تتكدس بأناقة، تختفي بدخان خفيف.
8. **Empty states:** أي قائمة فارغة → رسم زجاجي خفيف + رسالة محفزة + زر إجراء ("لا توجد تقارير بعد — أنشئ أول تقرير").
9. **Tooltips:** فقاعة زجاجية صغيرة مع سهم، 150ms، على الأيقونات والأزرار المختصرة.
10. **Scrollbars:** مخصصة ورفيعة (4–6px) شفافة تظهر بتوهّج عند التمرير — على السطحين.

**مبدأ ذهبي:** الحركة تُخضع للنظام — `reduced-motion` يعطّل كل الحركات غير الأساسية (فورًا عند `prefers-reduced-motion` على الويب، وتبديل في الإعدادات بالـ Desktop).

## 10. الشاشات النظامية (SYSTEM SCREENS) — لا تُهمل

## 14. قواعد مقدسة (SACRED RULES — إن خالفتها فشلت المهمة)

1. **لا وهم:** ممنوع `Math.random()`، setTimeout fake، بيانات hardcoded تظهر كحقيقة، زر بلا handler، handler فارغ، خدمة تعرض "تم الإصلاح" بدون تنفيذ. كل نتيجة = تنفيذ حقيقي → نتيجة حقيقية → عرض حقيقي. أي أداة لا تستطيع ربطها بمحرك حقيقي → تُعرض بحالة صادقة "غير متاحة بعد" (BLOCKED) — لا نجاح مزيف.
2. **لا إعادة بناء المحرك:** Desktop execution layer أثبت جاهزيته (83/83 اختبارًا، Runtime PASS). تعديله فقط إذا كان **ضروريًا** للتكامل وكان **أضيق** تعديل ممكن.
3. **لا كسر للبنية:** MVVM على Desktop، وهيكل components الحالي على الويب — طوّر داخل البنية الموجودة.
4. **لا كلمات تقنية للمستخدم:** أسماء شعبية ("نظّف جهازك")؛ التفاصيل التقنية داخل Diagnostics/"التفاصيل".
5. **لا Push، لا Force، لا Reset:** اعمل محليًا واعرض الـ diff. لا تلمس baseline `3066e54` ولا تعيد كتابة أي commit. لا تضف remote جديدًا.
6. **لا ملفات مولّدة في git:** `node_modules/` `dist/` `bin/` `obj/` `*.tsbuildinfo` `.env*` logs — كلها خارج التتبع.
7. **لا خطأ صامت:** فشل = رسالة بشرية + تشخيص تقني، دائمًا.
8. **الزجاج للناس:** كل تأثير زجاجي يجب ألا يكسر القراءة (تباين ≥4.5:1) ولا الأداء (لا blur زائد فوق محتوى متحرك ثقيل؛ الـ blur يُطبق على طبقات هادئة).
